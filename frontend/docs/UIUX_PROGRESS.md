# 프론트 UI/UX 구현 현황

대상은 「프론트 UIUX 간단 가이드」의 큰 항목 **2~5 전체**입니다. 첫 항목의 디자인 규칙은 적용하지 않고, 현재의 파랑·흰색과 KBO 화면 분위기를 유지합니다.

## 2. 여섯 화면

| 화면 | 주소 | 구현 범위 |
| --- | --- | --- |
| 메인 | `/` | 챗봇 질문, 티빙 당일 경기·선발 투수·좌우 이동, 일정 아래 10팀 순위표, 인기 코스 6개, 9개 구장 선택 |
| 로그인 | `/login` | 입력값 검사, 비밀번호 표시, 제출 상태·오류 안내, 소셜 로그인 진입 버튼 |
| 회원가입 | `/signup` | 회원 정보·비밀번호 확인, 정책 동의, 입력값 검사, 제출 상태·오류 안내 |
| 팬 커뮤니티 | `/routes` | 번호·제목·글쓴이·좋아요·조회·작성일 게시판, 제목/내용/작성자 검색, 9개 구장 필터, 최신순·좋아요순·조회순, 5/10/20개씩 보기, 페이지 이동, 글쓰기·상세 연결 |
| 루트 상세 | `/routes/[id]` | 본문, 지도·마커·방문 순서 연결선, 좋아요·공유, 내 코스 수정·삭제 확인 |
| 루트 작성·수정 | `/routes/new`, `?edit=코스ID` | 제목·구장·본문·방문 장소 편집, 지도·검색 연결, 챗봇 보조, 기기 저장 |

기존 `/stadiums`와 `/guide`도 유지합니다. 상단은 **KBO 로고·카테고리 메뉴·로그인·회원가입**을 표시합니다. 로그인 왼쪽 햄버거 버튼에서 메인, 경기(구장 정보·경기 일정·순위·야구 가이드), AI 루트(작성·둘러보기), 챗봇으로 이동합니다. 경기 일정 `/schedule`은 2026년 월·날짜 선택, 구단 필터, 경기 결과·선발·구장을 표시합니다. 순위 `/standings`는 팀 순위 전체 12개 항목과 기록별 정렬을 제공합니다. 메인과 상세 화면은 같은 수집 결과를 사용합니다. 챗봇은 기존 대화·팝업 전환 상태를 유지하며 대형 화면을 엽니다.

사용자 추가 요청에 따라 `/chat` 전용 대화 화면과 작은 직관 도우미 팝업을 구성했습니다. 메인 질문 전송은 전용 페이지로 이동하고, 바깥 페이지의 직관 도우미 버튼은 팝업을 엽니다. 팝업의 크게 보기와 전용 페이지의 작게 보기로 전환하며 대화·초안·진행 중인 응답을 공유합니다. 전용 페이지는 별도 대화 목록·하단 입력창을 사용하고 일반 헤더·푸터·모바일 메뉴와 직관 도우미 버튼을 숨깁니다. 대화와 작성 중인 루트는 클라이언트 페이지 이동 중 유지되며, 서버에 대화 이력을 저장하는 기능은 아직 없습니다.

## 3. 반응형

- 메인 루트 카드: 768px 미만 1열, 768~1023px 2열, 1024px 이상 3열. 커뮤니티는 PC·태블릿에서 표, 모바일에서는 제목 아래 작성자·날짜·조회·좋아요를 표시하는 목록으로 전환합니다.
- 모바일 하단 탐색, 가로로 넘기는 구장 필터, 작은 화면의 폼·대화창·확인 모달 대응.
- 키보드 포커스, 입력 레이블, 오류·완료 상태 안내, 모션 감소 설정 대응.
- **360px / 768px / 1440px**에서 여섯 화면의 가로 넘침이 없음을 확인했습니다. 목록·메인 카드의 1/2/3열과 작성 화면의 모바일 탭·태블릿 세로·PC 2열도 확인했습니다.

## 4. 로딩·오류·빈 상태

- 목록·상세: 화면 이동과 저장 데이터 확인 중 스켈레톤.
- 목록: 검색 결과가 없으면 첫 코스 작성·전체 보기 제공.
- 지도: SDK 로딩, 실패 시 다시 시도와 외부 카카오맵 안내.
- 챗봇: 응답 대기, 취소·재시도, 오류 시 질문 보존.
- 폼·저장: 입력 오류, 처리 상태와 저장 실패 안내.
- 삭제: 브라우저 기본 확인창 대신 확인 모달과 삭제 후 완료 안내.

## 5. 제작·인계 순서

1. 기존 색상과 공통 버튼·폼·카드·탐색을 기준으로 여섯 화면을 구성합니다.
2. 로그인·회원가입 입력 흐름과 목록·상세의 상태를 연결합니다.
3. 루트 작성 → 기기 저장 → 상세 → 수정·삭제 흐름을 연결합니다.
4. 지도·챗봇·에디터 연결 지점을 분리하고 모바일·로딩 상태를 확인합니다.
5. 아래 실제 서비스 연결을 완료한 뒤 팀 API 기준으로 다시 검증합니다.

## 실제 서비스 연결 상태

| 항목 | 현재 상태 | 다음 작업 |
| --- | --- | --- |
| 회원·소셜 로그인 | 화면과 입력 검사는 구현. 인증 API 미연결 | 회원 API, 세션, 정책 문구, 작성자 권한 연결 |
| 게시글·좋아요·조회 | 이 브라우저의 저장소 사용 | 팀 게시글 API와 DB로 교체 |
| 공유 | 샘플은 링크, 내 코스는 내용을 공유 | 게시글 API 연결 후 실제 공개 링크 제공 |
| 경기·순위 | 티빙 공개 데이터를 공통 수집. 메인은 당일 미리보기, 일정 페이지는 2026년 기록, 순위 페이지는 전체 팀 기록 표시. 서버 로컬 파일 저장 | 운영 시 팀 DB·수집 워커로 이전. [수집 안내](KBO_DATA.md) |
| 코스 예시 | 샘플 코스 6개. 실제 이용 후기 아님 | 실제 게시글 데이터 연결 |
| 카카오맵 | SDK·검색·마커·방문 순서 연결선 코드 구현. 현재 로컬 SDK 요청은 401로 표시되지 않음 | 사용 중인 카카오 앱에 `http://localhost:3000` 웹 도메인을 등록한 뒤 재확인 |
| CKEditor 5 | 라이선스 설정과 어댑터 준비. 사용자 선택에 따라 현재는 일반 본문 입력 사용 | 적절한 라이선스 확보 후 `NEXT_PUBLIC_CKEDITOR_LICENSE_KEY` 설정·재시작·검증 |
| AI 챗봇 | Luna 직접 연결. 구장·일정·테마를 질문에 전달 | 팀 RAG와 실제 경기·장소 데이터 연결 |

카카오맵의 연결선은 저장한 장소의 순서를 표시하며 실제 도보·교통 경로 계산 결과가 아닙니다. 로컬 저장 코스는 로그인 사용자 권한 검증이나 서버 공개 게시글을 대신하지 않습니다.

### 이번 확인 결과

- 메인의 ‘루트 둘러보기’는 `/routes`의 팬 커뮤니티로 이어집니다. [참고 게시판](https://demo.sir.kr/gnuboard5/bbs/board.php?bo_table=free)의 제목 중심 표 구성을 현재 파랑·흰색 디자인에 맞춰 적용했습니다. 홈의 인기 코스 카드는 유지합니다.
- 커뮤니티에서 검색 범위 3종, 구장 필터·빈 결과·조회순 정렬·5개씩 페이지 이동, 글쓰기 → 기기 저장 → 목록 반영 → 상세 → 삭제를 확인했습니다. 검증용 임시 글은 삭제했습니다. 실제 이용자 사이의 공개·공유는 게시글 DB/API 연결 후 가능합니다.

- 브라우저에서 가입 필수 동의 전 버튼 비활성화, 선택 동의 없이 활성화, 입력 오류와 약관·계정 안내 모달을 확인했습니다.
- 로그인·회원가입의 초기 서버 HTML은 입력·제출을 비활성화하고 POST 방식을 사용합니다. 화면 준비 전 인증 정보가 URL에 제출되는 문제를 방지했습니다.
- 임시 코스로 장소 추가·순서 변경·탭 전환 중 내용 유지·덮어쓰기 취소·저장·수정·좋아요 토글·삭제를 확인하고 임시 코스를 삭제했습니다. 샘플 상세에는 수정·삭제가 표시되지 않습니다.
- 구장 필터의 빈 결과와 삭제 완료 안내, 메인 코스 6개·구장 링크 9개를 확인했습니다.
- 빌드, ESLint, 챗봇 테스트 40개, 본문 변환·링크 테스트 22개 통과.
- 실제 카카오 지도·장소 검색은 도메인 등록 후, CKEditor 실제 초기화는 라이선스 설정 후 검증해야 합니다. 이 두 항목과 Docker 구동은 완료로 표시하지 않습니다.

### 로컬 지도와 에디터 설정

`frontend/.env.local`에 지도용 **JavaScript 키**를 `NEXT_PUBLIC_KAKAO_MAP_KEY`로 설정합니다. 카카오 REST 키나 OpenAI 키에는 `NEXT_PUBLIC_`를 붙이지 않습니다. 현재 키는 기존 루트 환경 파일에서 JavaScript 키만 복사해 적용했습니다.

[카카오 공식 설정 안내](https://apis.map.kakao.com/web/guide/)에 따라 해당 JavaScript 키의 SDK 도메인에 `http://localhost:3000`을 등록합니다. 팀 Docker의 `http://localhost`도 별도로 등록합니다. 이번 로컬 요청은 `401 domain mismatched`를 반환했습니다.

CKEditor용 `NEXT_PUBLIC_CKEDITOR_LICENSE_KEY`는 현재 비워 둡니다. 사용할 라이선스가 정해지면 이 값만 설정하고 프론트 서버를 재시작하여 서식 입력을 검증합니다. 일반 글쓰기와 기존 저장 코스는 그대로 이용할 수 있습니다.
